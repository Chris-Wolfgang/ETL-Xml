# Migrating from v0.8 to v0.9

## Prerequisites

Install the new NuGet package:

```
dotnet add package Wolfgang.Etl.Xml --version 0.9.0
```

v0.9 references `Wolfgang.Etl.Abstractions` 0.24, which introduces the per-stage-kind base records (`ExtractorOptions`, `LoaderOptions`) that this release builds on. Pre-1.0: breaking changes are listed here rather than deferred to a major version.

---

## Breaking Changes

| API | Before | After | Reason |
|-----|--------|-------|--------|
| `XmlSingleStreamLoader<T>`, `XmlMultiStreamLoader<T>` | implement `ISupportDryRun` | do not | Abstractions 0.24 removes the interface; dry run is construction-time configuration through the loader's options record (ADR-0009) |
| `XmlSingleStreamExtractorOptions`, `XmlSingleStreamLoaderOptions` | `sealed class` | `sealed record` inheriting `ExtractorOptions` / `LoaderOptions` | one options record per stage carrying the inherited settings too. Every existing initializer compiles unchanged; only code that relied on reference equality between two option instances would notice |

---

## Deprecations

| Deprecated API | Replacement | Removed In |
|----------------|-------------|------------|
| `XmlSingleStreamLoader<T>.IsDryRun` setter | `XmlSingleStreamLoaderOptions.IsDryRun` | a later release, after this deprecation has shipped |
| `XmlMultiStreamLoader<T>.IsDryRun` setter | `XmlMultiStreamLoaderOptions.IsDryRun` | same |

Only the **setter** accessor is `[Obsolete]`; reading the properties stays warning-free.

Fifteen constructors are hidden from IntelliSense (`[EditorBrowsable(Never)]`) but **retained permanently** for binary compatibility. Existing calls keep compiling and keep binding to them; new code has no reason to name them:

- the single-argument constructors (`(stream)`, `(streams)`, `(streamFactory)`, `(bufferWriterFactory)`, and the `(source, options)` / `(source, logger)` two-argument forms), superseded by `(source, options, logger)`;
- every constructor that took `XmlReaderSettings` / `XmlWriterSettings` positionally, superseded by `ReaderSettings` / `WriterSettings` on the record.

---

## The new shape: one options record per stage

| Stage | Record | Own members | Inherited |
|-------|--------|-------------|-----------|
| `XmlSingleStreamExtractor<T>` | `XmlSingleStreamExtractorOptions` | `ReaderSettings`, `LeaveOpen` | `ReportingInterval`, `MaximumItemCount`, `SkipItemCount`, `ErrorPolicy` |
| `XmlMultiStreamExtractor<T>` | `XmlMultiStreamExtractorOptions` | `ReaderSettings` | same |
| `XmlSingleStreamLoader<T>` | `XmlSingleStreamLoaderOptions` | `WriterSettings`, `RootElementName`, `LeaveOpen`, `IsDryRun` | same |
| `XmlMultiStreamLoader<T>` | `XmlMultiStreamLoaderOptions` | `WriterSettings`, `IsDryRun` | same |

The reader/writer settings travel on the record as the `XmlReaderSettings` / `XmlWriterSettings` instance itself; nothing is flattened.

```csharp
// before (v0.8)
var extractor = new XmlSingleStreamExtractor<Person>(stream, readerSettings, logger);
var loader = new XmlMultiStreamLoader<Person>(record => OpenFile(record)) { IsDryRun = true };

// after (v0.9)
var extractor = new XmlSingleStreamExtractor<Person>
(
    stream,
    new XmlSingleStreamExtractorOptions { ReaderSettings = readerSettings, MaximumItemCount = 1_000 },
    logger
);
var loader = new XmlMultiStreamLoader<Person>(record => OpenFile(record), new XmlMultiStreamLoaderOptions { IsDryRun = true });
```

A stage constructed without a record keeps every default, exactly as before.

- [ ] Move post-construction assignments to `IsDryRun` into the matching options record (the compiler warning names it).
- [ ] Optionally move positional `XmlReaderSettings` / `XmlWriterSettings` arguments onto the record; the old overloads keep working.
